# 4. Фокус на результат поиска

**Платформа:** браузерное расширение

## Концепция

Расширение для браузера: когда пользователь переходит на сайт по ссылке из поисковой выдачи, страница сразу прокручивается к фрагменту, который соответствует запросу, и этот фрагмент подсвечивается. Не нужно вручную искать через Ctrl+F, где на длинной странице ответ.

Похожий механизм частично есть в Google (Text Fragments, `#:~:text=` для featured snippets), но работает только для отдельных результатов и только в одном поисковике. Расширение делает это для любой ссылки и любого поисковика.

## Ключевые фичи

### MVP
- Перехват клика по результату в выдаче Google, Яндекса, Bing, DuckDuckGo.
- Сохранение поискового запроса и сниппета результата.
- На открытой странице: поиск фрагмента, наиболее похожего на сниппет / запрос, прокрутка к нему и подсветка.
- Если совпадений несколько — навигация «следующее / предыдущее» в маленькой плашке.
- Подсветка всех слов запроса на странице (переключаемо).
- Кнопка отключения на конкретном сайте.

### Следующие версии
- Нечёткое совпадение: морфология (русский язык), синонимы, перефразировки.
- Семантический поиск фрагмента с локальной моделью эмбеддингов (без отправки страницы на сервер).
- Поддержка SPA и страниц с ленивой подгрузкой контента.
- Работа с PDF, открытыми в браузере.
- Краткий ответ на запрос прямо в плашке (по фрагменту страницы).
- Поддержка ссылок из ИИ-поисковиков и чатов (Perplexity, ChatGPT и др.).

### Монетизация (вариант)
- Базовая функция бесплатно (это ключ к установкам).
- Pro: семантический поиск, PDF, ответ на запрос. Или полностью бесплатный open-source проект для портфолио.

## Вопросы, на которые нужно ответить

1. **Как надёжно получить запрос и сниппет?** Разметка выдачи поисковиков часто меняется; из URL можно достать `q`/`text`, но сниппет — только парсингом DOM. Как держать селекторы актуальными?
2. **Как сопоставлять текст?** Сниппет поисковика часто склеен из нескольких кусков страницы и содержит «...». Точное совпадение, нечёткое (n-граммы, Левенштейн) или семантическое? Что даёт лучшее соотношение точности и скорости?
3. **Что делать с динамическими страницами?** Контент может подгружаться после загрузки, страница может перерисовываться. Сколько ждём и когда сдаёмся?
4. **Приватность.** Расширению нужен доступ ко всем сайтам и к поисковым запросам — это пугает пользователей и ревьюеров магазинов. Принцип «всё локально, ничего не отправляется» — обязательное требование?
5. **Какие браузеры первыми?** Chrome (Manifest V3) покрывает Chrome, Edge, Яндекс Браузер, Opera; Firefox и Safari — отдельно. Достаточно ли Chromium для старта?
6. **Насколько это мешает?** Неожиданная прокрутка может раздражать (например, при переходе на главную страницу сайта). Нужно ли подтверждение, порог уверенности, плашка «перейти к фрагменту» вместо автоматической прокрутки?
7. **Конкуренты.** Есть ли расширения с той же функцией и что в них не работает?

## План реализации

### Этап 0. Исследование (1 неделя)
- Изучить аналоги и стандарт Text Fragments (вопрос 7).
- Собрать 50 пар «запрос + сниппет + URL страницы» из разных поисковиков как тестовый набор.
- Решить вопросы 4, 5, 6.

### Этап 1. Алгоритм поиска фрагмента (1–2 недели)
- Офлайн-скрипт: страница + запрос + сниппет → найденный фрагмент.
- Сравнение подходов (точное, нечёткое, по частям сниппета) на тестовом наборе.
- Цель: правильный фрагмент найден в 80%+ случаев за < 100 мс.

### Этап 2. MVP-расширение для Chromium (2–3 недели)
- Manifest V3, content script для страниц выдачи Google и Яндекса.
- Передача запроса и сниппета в открываемую вкладку (storage + сопоставление по URL).
- Content script на целевой странице: поиск, прокрутка, подсветка, плашка навигации.
- Настройки: вкл/выкл, список исключённых сайтов, авто-прокрутка или по кнопке.

### Этап 3. Устойчивость (2 недели)
- Повторные попытки для динамических страниц (MutationObserver с таймаутом).
- Поддержка Bing и DuckDuckGo.
- Морфология русского языка (стемминг) для подсветки слов запроса.
- Ручное тестирование на 100 популярных сайтах.

### Этап 4. Публикация (1–2 недели)
- Публикация в Chrome Web Store (и Edge Add-ons), политика конфиденциальности, скриншоты.
- Сбор обратной связи и анонимной статистики «фрагмент найден / не найден» (только при согласии).

### Этап 5. Расширения (по результатам)
- Firefox, семантический поиск локальной моделью, PDF.

### Критерий успеха MVP
Расширение находит нужный фрагмент в 8 из 10 переходов из выдачи; не более 5% пользователей отключают авто-прокрутку в первую неделю.
